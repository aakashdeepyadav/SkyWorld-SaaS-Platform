## Executive Summary

### The Opportunity

**SkyWorld** is a production-grade B2B SaaS platform that enables digital agencies, freelancers, and studios to offer, track, and deliver three premium services:

- 🎨 **App Development** — Mobile and custom application development
- 🌐 **Web Development** — Full-stack web application development
- 🎭 **Branding & Creative** — Logo design, branding, and creative services

### Why SkyWorld?

The $150B+ digital services market is fragmented. Small agencies lack:

- Professional project management systems
- Integrated payment processing
- Transparent client communication
- Scalable service delivery workflows
- Real-time collaboration tools
- Audit trails and compliance features

SkyWorld solves these problems with a **white-label, role-based SaaS platform** that:

- ✅ Reduces delivery friction by 60%
- ✅ Increases client retention through transparency
- ✅ Automates invoicing and payment reconciliation
- ✅ Provides enterprise-grade security (OWASP compliant)
- ✅ Supports unlimited parallel projects
- ✅ Scales from solo freelancer to 500+ person studio

### Database Schema Overview

**9 MongoDB Collections:**

1. **Users** (50K projected)
   - Email, password (bcrypt hashed), name, role, avatar, phone, lastLogin
   - Indexes: email (unique), googleId (unique/sparse), role, isActive, createdAt

2. **Services** (50 total)
   - name, description, category, basePrice, isActive
   - Categories: app-development, web-development, branding-creative

3. **ServiceRequests** (20K projected)
   - clientId, serviceId, title, description, status, assignedDeveloperId, estimatedPrice
   - Status: pending → approved → in-progress → completed

4. **CustomRequests** (5K projected)
   - clientId, description, budget, files[], quotedPrice, status, quotedAt

5. **Projects** (20K projected)
   - serviceRequestId, clientId, developerIds[], title, status, progress (0-100), budget, milestones[]
   - Status: planning → in-progress → review → completed

6. **Payments** (30K projected)
   - clientId, projectId, amount, currency, status, transactionId, invoiceNumber, paidAt
   - Integrations: Razorpay for payment processing

7. **Messages** (100K projected)
   - projectId, senderId, recipientId, content, attachments[], isRead, readAt
   - Real-time updates via Socket.IO

8. **Files** (50K projected)
   - projectId, uploadedBy, fileName, fileUrl (Cloudinary), fileType, fileSize, mimeType
   - Storage: Cloudinary with virus scanning capability

9. **AuditLogs** (500K projected)
   - userId, action, resource, resourceId, details, ipAddress, userAgent, timestamp
   - 90-day auto-cleanup TTL index

## Security Infrastructure

### Authentication & Authorization

#### Email/Password Flow

1. **Registration:**
   - Password validated: min 8 chars, 1 uppercase, 1 digit, 1 special char
   - Password hashed with bcrypt (cost: 10 rounds) — 100ms
   - Email OTP sent (6 digits, 10 min expiry)
   - User created with `emailVerified: false`

2. **Login:**
   - Email + password required
   - Account lockout after 5 failed attempts (30 minutes)
   - bcrypt comparison (secure timing)
   - JWT generated: Access (15 min) + Refresh (7 days)
   - Tokens stored in HttpOnly, Secure, SameSite cookies
   - Returns user profile (no sensitive data)

3. **Token Refresh:**
   - Uses refresh token (7 days validity)
   - Generates new access token (15 min)
   - Old refresh token invalidated (rotating scheme)

#### Google OAuth 2.0

1. **Authorization Code Flow:**
   - Frontend redirects to Google OAuth URL
   - User authenticates with Google
   - Backend exchanges code for tokens
   - Retrieves user profile (email, name, picture)

2. **User Handling:**
   - Email verified automatically (trusted Google source)
   - First login: Create user with role `client`
   - Subsequent logins: Sync profile if changed

#### Multi-Factor Authentication (2FA)

- **TOTP (Time-based One-Time Password):** Speakeasy library
- User setup: Scan QR code in authenticator app
- On login: Enter 6-digit code from authenticator
- Backup codes provided for account recovery

#### Password Reset

1. Client requests reset: `/auth/forgot-password` (email)
2. Reset token generated (1 hour expiry)
3. Email sent with reset link
4. Client visits reset link: `/reset-password?token=...`
5. Submit new password: `/auth/reset-password`
6. Token validated, password updated
7. Email confirmation sent

### Role-Based Access Control (RBAC)

**Three Roles with Strict Enforcement:**

| Aspect         | Admin                     | Developer               | Client                     |
| -------------- | ------------------------- | ----------------------- | -------------------------- |
| **Assignment** | Manual by admin           | Admin-assigned          | Default on signup          |
| **Authority**  | Full platform access      | Assigned projects only  | Own resources + purchases  |
| **Can create** | Projects, requests, users | Project updates         | Custom requests, orders    |
| **Dashboard**  | Analytics, user mgmt      | Task queue, performance | Project overview, invoices |

**Middleware-Level Enforcement:**

- `authenticate()` — Verifies JWT existence & validity
- `authorize(...roles)` — Checks if user role ∈ allowed roles
- `ownerOrAdmin(field)` — Validates resource ownership OR admin status
- `adminOnly` — Shorthand for `authorize('admin')`

**Frontend Route Guards:**

- `ProtectedRoute` — Requires authentication, redirects to `/login`
- `RoleRoute` — Requires specific role, redirects to role-specific dashboard
- Sidebar navigation changes based on role
