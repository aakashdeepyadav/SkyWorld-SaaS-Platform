## Account Setup

### Step 1: Create Your Developer Account

#### Application Process

1. Go to [skyworld.com/developers](https://skyworld.com/developers)
2. Click **"Join as Developer"**
3. Fill in the form:
   - **Full Name:** Your name
   - **Email:** Valid email address
   - **Password:** Strong password (8+ chars, 1 uppercase, 1 number, 1 special)
   - **Phone Number:** For communication
   - **Timezone:** Your working timezone
4. Click **"Create Account"**

#### Email Verification

1. Check your email for verification link from **noreply@skyworld.com**
2. Click the **verification link**
3. Your account is now active! ✅

> **Important:** Only verified accounts can receive project assignments.

### Step 2: Complete Developer Profile

This is CRITICAL - clients see your profile before assigning projects!

#### Go to Developer Profile Setup

1. After login, you'll see **"Complete Your Profile"** banner

## Understanding Projects

#### 1. Web Development Projects

**Examples:**

- Business websites
- E-commerce stores
- Web applications
- Landing pages
- Content management systems

**Typical requirement:** "Build a responsive website with 5-8 pages, contact form, and admin panel"

**Timeline:** 2-6 weeks

**Team:** Usually 1 developer or small team

---

#### 2. App Development Projects

**Examples:**

- Mobile apps (iOS/Android)
- Progressive web apps
- Cross-platform solutions
- Startup MVPs
- Custom applications

**Typical requirement:** "Build a mobile app with user authentication, real-time database, and payment integration"

**Timeline:** 4-12 weeks

**Team:** Usually 2-5 developers

---

#### 3. Branding & Design Projects

**Examples:**

- Logo design
- Brand identity
- Social media assets
- Marketing materials
- UI/UX design

**Typical requirement:** "Design a complete brand identity including logo, color palette, and typography"

**Timeline:** 2-4 weeks

**Team:** Usually designer + brand strategist

### Project Assignment

#### How You Get Projects

1. **Admin Reviews:** Admin reviews available projects
2. **Skill Matching:** Admin matches project to your skills
3. **Team Building:** Admin assigns best fit developers
4. **Notification:** You get notified of assignment
5. **Acceptance:** Click "Accept" to confirm

#### Accepting a Project

When you're assigned a project, you'll see:

1. **Notification:** Email + in-app notification
2. **Project Details:**
   - Client name (sometimes anonymous at first)
   - Project description
   - Requirements
   - Budget/compensation
   - Timeline
   - Milestones

3. **Your Options:**
   - ✅ **Accept** — You commit to the project
   - ❌ **Decline** — You can't work on this (give reason)
   - ❓ **Request More Info** — Ask clarifying questions

#### Can I Turn Down Projects?

Yes! But use wisely:

- 1-2 declines per month: No penalty
- 3+ declines: May affect future assignments
- Be professional in decline reason

## Project Workflow

### Understanding the Project Lifecycle

```
1. ASSIGNMENT          2. KICKOFF
   ├─ You're assigned     ├─ Review requirements
   │                      ├─ Ask clarifying questions
   └─ Accept project      └─ Plan approach

3. DEVELOPMENT         4. MILESTONE COMPLETION
   ├─ Work on milestones  ├─ Upload deliverables
   ├─ Update progress     ├─ Add completion notes
   └─ Stay in touch       └─ Request client feedback

5. REVISIONS (if needed) => Re-work and re-submit

6. PROJECT COMPLETION  7. PAYMENT & DELIVERY
   ├─ All done            ├─ Final payment confirmed
   ├─ Client reviews      ├─ Files transferred to client
   └─ Final delivery      └─ Project closed

8. FEEDBACK COLLECTION
   ├─ Client rates you
   └─ Review appears on profile
```

### Detailed Workflow

#### Step 1: Project Assignment

**What You See:**

- Email: "New Project Assigned: [Project Name]"
- In-app notification with project summary

**What To Do:**

1. Click notification to view full details
2. Read project requirements carefully
3. Review timeline and milestones
4. Check expected compensation
5. Click **"Accept Project"** if ready

---

#### Step 2: Project Kickoff

**First 24-48 Hours:**

1. **Review Everything:**
   - Client requirements
   - Milestone breakdown
   - Expected deliverables
   - Timeline for each milestone
   - Success criteria

2. **Ask Clarifying Questions:**
   - Click "Messages" section
   - Ask specific questions:
     - "What are the exact requirements for authentication?"
     - "Should the app be responsive?"
     - "Do you have brand guidelines?"
     - "What's your expected load/users?"

3. **Create Your Plan:**
   - List tech/tools you'll use
   - Break down milestones into tasks
   - Estimate effort per milestone
   - Identify dependencies

4. **Share Your Approach:**
   - Message client: "Here's how I'll approach this..."
   - Include timeline, tech stack, deliverables
   - Get buy-in before heavy coding

**Example Message:**

```
Hi [Client Name],

I'm excited to work on this project! Here's my approach:

Technology Stack:
- Frontend: React + Tailwind CSS
- Backend: Node.js + Express
- Database: MongoDB
- Hosting: Vercel + Render

Timeline:
- Week 1: Design & Setup
- Week 2: Core Features
- Week 3: Testing & Refinement
- Week 4: Deployment & Handoff

I'll start with the design mockups this week and share
progress updates twice weekly.

Do you have any questions or changes to this plan?

Best,
[Your Name]
```

---

#### Step 3: Active Development

**During the project:**

1. **Work on Milestones:**
   - Focus on one milestone at a time
   - Break it into smaller tasks
   - Commit to timeline

2. **Update Progress:**
   - Update progress slider as you complete work
   - Add notes about what's done
   - Mark milestone status: Pending → In Progress

3. **Stay in Touch:**
   - Send progress updates 2x per week (minimum)
   - Respond to messages within 24 hours
   - Ask for feedback on completed work
   - Address concerns immediately

4. **Upload Work:**
   - Upload code, designs, prototypes regularly
   - Add comments explaining changes
   - Tag files with milestone name

---

#### Step 4: Milestone Completion

**When a milestone is fully done:**

1. **Prepare Deliverables:**
   - Code: Push to repo, clean up
   - Design: Export assets, organize files
   - Documentation: Add comments, create readme
   - Testing: QA your work

2. **Upload to Project:**
   - Go to **Files** section
   - Click **"Upload Milestone Deliverables"**
   - Upload files:
     - Code repo link
     - Design files (Figma, XD, PSD)
     - Screenshots/preview
     - Documentation
     - Setup instructions

3. **Add Completion Notes:**

   ```
   Milestone: Design Phase (COMPLETED)

   Deliverables:
   - 3 Homepage design concepts
   - Initial wireframes for all pages
   - Color &typography guidelines
   - Design system components

   Notes:
   - Design ready for review
   - Recommended next: Frontend dev
   - Please share feedback on choice between Option A vs B

   Completion Date: March 15, 2026
   ```

4. **Mark as Complete:**
   - Click **"Mark Milestone Complete"**
   - Set completion date
   - Click **"Upload"**

5. **Get Client Feedback:**
   - Client reviews deliverables
   - Provides feedback/approvals
   - You can implement changes

---

#### Step 5: Revisions (If Needed)

**If client requests changes:**

1. **Review Feedback:**
   - Read client's comments carefully
   - Identify what needs to change
   - Assess scope: Small tweak? or Major rework?

2. **Ask for Clarity:**
   - "When you say 'bigger buttons', do you mean 1.5x current size?"
   - Get specific requirements
   - Agree on revision timeline

3. **Implement Changes:**
   - Update files
   - Re-upload to project
   - Highlight what changed

4. **Get Approval:**
   - Message: "Revisions complete, please review"
   - Wait for client approval
   - If approved, mark as done

**Note:** Usually 2-3 revision rounds are included. Major scope changes may require additional compensation.

---

#### Step 6: Project Completion

**When all work is done:**

1. **Final Quality Check:**
   - Review all deliverables
   - Test everything works
   - Check for bugs or issues
   - Ensure documentation is clear

2. **Final Delivery:**
   - Upload all final files
   - Create comprehensive README
   - Include setup instructions
   - Provide access credentials if needed
   - Mark project **"Ready for Final Delivery"**

3. **Client Review:**
   - Client downloads all files
   - Tests everything
   - Requests final changes if any

4. **Project Closure:**
   - Client approves final delivery
   - Project status: **"Completed"** ✅
   - Prepare for payment

---

#### Step 7: Payment & Feedback

**Post-completion:**

1. **Payment:**
   - Final payment is processed
   - You receive notification
   - Payment appears in your wallet

2. **Feedback:**
   - Client leaves review/rating
   - Review appears on your profile
   - You can reply to feedback

3. **Project Archived:**
   - Project moves to "Completed" section
   - Still accessible for reference
   - Files remain available

## Managing Tasks & Milestones

### Understanding Milestones

Each project has **2-5 milestones:**

| Milestone       | Example                 | Deliverables                       | Timeline |
| --------------- | ----------------------- | ---------------------------------- | -------- |
| **Design**      | Homepage & pages design | Wireframes, mockups, design system | Week 1-2 |
| **Development** | build all features      | Working code, database setup       | Week 2-4 |
| **Testing**     | QA and bug fixes        | Test reports, fixed bugs           | Week 4-5 |
| **Deployment**  | Launch to production    | Live website, documentation        | Week 5-6 |

### Updating Milestone Status

Each milestone has a status:

```
Pending       In Progress    Completed
   ◯     →         ◐      →       ●
 (Start)      (Working on)    (Done)
```

**How to Update:**

1. Go to **Project → Milestones**
2. Find milestone you're working on
3. Click **"Update Status"**
4. Choose status:
   - **Pending:** Not started
   - **In Progress:** Currently working
   - **Completed:** Fully done
5. Click **"Save"**

### Progress Slider

**Update overall project progress:**

1. Go to **Project → Progress**
2. Drag slider to indicate % complete:
   - 0% = Just started
   - 25% = First milestone done
   - 50% = Halfway through
   - 75% = Almost done
   - 100% = Complete

3. This shows client real-time progress

**Example:**

```
Design Phase Complete       => 25% overall
+ Development started       => 50% overall
+ Testing phase complete    => 75% overall
+ Ready for deployment      => 100% overall
```

## Communication & Collaboration

### Messaging Features

#### Sending Messages

1. Go to **Project → Messages** section
2. Type message in text box
3. Click **"Send"** or press Enter
4. Message appears instantly

#### Message Types

**Status Update:**

```
✅ COMPLETED design phase! All 3 homepage mockups ready.
Please review by [date] so we can proceed with development.
Check the Files section for design files.
```

**Clarification Question:**

```
Question about the requirements: You mentioned "user dashboard"
- Should this include admin access, or just user view?
- How many user roles (admin, editor, viewer, etc.)?
```

**Asking for Feedback:**

```
I've uploaded the initial designs. Could you review and let me
know your thoughts? Specifically:
1. Do these match your brand vision?
2. Any changes to the layout?
3. Color scheme - works for you?
```

**Daily/Weekly Update:**

```
Weekly Update (March 1-7):
✅ Completed user authentication
✅ Set up database schema
🟡 In Progress: API endpoints (50% done)
⏭️ Next: Payment integration

No blockers. Project on track for March 15 deadline.
```

### Best Practices

**Communication Tips:**

1. **Be Clear:** Specific, concise messages
2. **Be Professional:** Friendly but business-like
3. **Be Responsive:** Reply within 24 hours
4. **Be Proactive:** Give updates without being asked
5. **Escalate Issues:** Contact admin if stuck or major blocker

**What NOT to Do:**

- ❌ Don't disappear for days without updates
- ❌ Don't ignore client messages
- ❌ Don't make major changes without approval
- ❌ Don't save bad news for later
- ❌ Don't argue with client (professional always)

### Scheduling Meetings

**If you need to discuss in detail:**

1. In messages, suggest: "Let's hop on a quick call. Are you available [date/time]?"
2. Provide meeting link (Zoom, Google Meet, Skype)
3. Send calendar invite
4. Meet and discuss
5. Share summary notes afterward

## File Management

### Uploading Files

#### Upload Project Files

1. Go to **Project → Files**
2. Click **"Upload Files"**
3. Select files from computer
4. Add description:
   ```
   Milestone: Design Phase
   - Homepage mockups (3 designs)
   - Color palette & typography
   - Design system component guide
   ```
5. Click **"Upload"**

#### File Types Accepted

| Type          | Examples                               |
| ------------- | -------------------------------------- |
| **Code**      | .js, .jsx, .tsx, .py, .java, .rb, .zip |
| **Design**    | .figma, .xd, .psd, .sketch, .png, .svg |
| **Documents** | .pdf, .doc, .docx, .txt, .md           |
| **Media**     | .jpg, .png, .mp4, .mov                 |
| **Archives**  | .zip, .rar, .tar                       |

**Max file size:** 50MB per file  
**Max per project:** 500MB total

### Organizing Files

**File Naming Convention:**

```
[Milestone]_[Version]_[Date]
├─ Design_v1_Mar-01
├─ Design_v2_Mar-05  (includes revisions)
├─ Development_Backend_Mar-10
├─ Development_Frontend_Mar-12
└─ Testing_BugFixes_Mar-15
```

### Sharing Code

**Best Practices:**

1. **Use Version Control:**
   - Push code to GitHub (private repo)
   - Share GitHub link in project
   - Include README with setup instructions

2. **Share Access:**
   - Add client as collaborator (if needed)
   - Create separate branch for review
   - Document code clearly

3. **Live Preview:**
   - Deploy to staging URL
   - Share link so client can test
   - Password protect if confidential

**Example:**

```
Files Uploaded: Design Phase Complete

GitHub Repo: https://github.com/dev/project-xyz
Branch: development (master is production ready)

To run locally:
1. git clone [repo]
2. npm install
3. npm start

Staging URL: https://staging.example.com
(Use credentials provided in private message)

All design files in /design folder
```

## Account Settings

### Profile Management

#### Update Profile

1. Go to **Settings → Profile**
2. Update:
   - Name, photo, bio
   - Phone, timezone
   - Skills, experience level
   - Rate/availability

3. Click **"Save Changes"**

#### Change Password

1. Go to **Settings → Security**
2. Click **"Change Password"**
3. Enter:
   - Current password
   - New password (8+ chars)
   - Confirm new password
4. Click **"Update"**

#### Two-Factor Authentication

**Enable 2FA for security:**

1. Go to **Settings → Security**
2. Click **"Enable 2FA"**
3. Download authenticator app (Google Authenticator, Authy)
4. Scan QR code
5. Enter 6-digit code
6. Save backup codes safely

#### Set Availability

1. Go to **Settings → Availability**
2. Select hours you're available:
   - Timezone
   - Working hours
   - Days per week
   - Concurrent projects (how many at once)

3. Click **"Save"**

**Example:**

```
Timezone: IST (UTC+5:30)
Available: Mon-Fri, 10AM-8PM IST
Concurrent Projects: 2-3 simultaneous
Max Hours/Week: 40 hours
```

## FAQ & Troubleshooting

### Account & Onboarding

**Q: How long does verification take?**
A: Usually 2-4 hours. Check spam folder if you don't get email.

**Q: Do I need a portfolio to start?**
A: Not required, but strongly recommended. Projects show in profile and help get better assignments.

**Q: Can I list experience I don't have?**
A: No. Be honest. Taking projects outside your expertise leads to poor reviews and removal.

**Q: How often do I get projects?**
A: Depends on:

- Your skills match
- Your availability
- Your rating (higher = more)
- Your response rate

Usually: 1-3 projects per month for new developers.

---

### Projects & Assignments

**Q: Can I turn down a project?**
A: Yes, but limit to 2-3 per month. Too many declines affect future assignments.

**Q: What if I can't complete a project?**
A: Communicate ASAP! Contact admin explaining situation. Abandoning projects seriously damages your profile.

**Q: Can I work with my own team?**
A: Yes! You can subcontract to your team. Just ensure quality and timeline are met.

**Q: Are NPAs required?**
A: Generally no, but some clients may request. Standard SkyWorld agreement covers IP.

**Q: Who owns the code/design I create?**
A: Client owns it. You cannot reuse client-specific code for other projects.

---

### Milestones & Deliverables

**Q: Can I change the milestone structure?**
A: Only with admin approval. Work with client to agree on changes.

**Q: What if I finish early?**
A: Great! Notify client and admin. You can request early completion bonus or move to next milestone early.

**Q: How many revision rounds?**
A: Usually 2-3 included. Additional revisions may require renegotiation.

**Q: What counts as a "revision"?**
A: Minor tweaks (color change, text update). Major redesigns = scope change = additional cost.

---

### Communication & Files

**Q: How quickly should I respond to messages?**
A: Within 24 hours ideally. Your response time affects rating.

**Q: Can I take client contact info to work independently?**
A: No. Circumventing SkyWorld is against terms. Keep all communication on platform.

**Q: What's the best way to share code?**
A: Private GitHub repo or SkyWorld file uploads. Never share in messages (hard to track).

**Q: How large can files be?**
A: Max 50MB per file. Use GitHub for large codebases.

### Payment & Earnings

**Q: When do I get paid?**
A: After client pays final 50% and admin approves project completion (usually 1-2 weeks).

**Q: Can I request payout anytime?**
A: Yes, but minimum is $50. Takes 3-5 business days to receive.

**Q: What about refunds if client disputes?**
A: Rare, but disputes are settled through admin review. Quality work protects you.

**Q: Any fees or commissions?**
A: SkyWorld takes ~15% commission. Rest goes to you.

**Example:** $1,000 project

- SkyWorld: $150
- You get: $850

**Q: Are taxes my responsibility?**
A: Yes. Freelancer taxes are your responsibility. Keep records of all earnings.

### Performance & Reviews

**Q: How can I improve my rating?**
A: Deliver on time, communicate well, write clean code, be responsive.

**Q: Can I respond to bad reviews?**
A: Yes. Click "Reply" to provide context professionally. Don't argue.

**Q: Does a bad project hurt my overall rating?**
A: Yes, but newer projects have more weight. Improve and move on.

**Q: How many reviews do I need to be "featured"?**
A: 10+ reviews at 4.5+ stars puts you in recommended list.

A: Check file size (<50MB), format, internet connection. Try different browser.

**Q: Is my communication secure?**
A: Yes. All messages encrypted. No one sees except you, client, and admin (if needed).

**Q: How do I report a problem?**
A: Contact support@skyworld.com with details. Response within 24 hours.
